Normal querying:

..> Retrieve documents that match a condition.

..> Use Case:	Simple data retrieval.

..> it can  not do the Grouping, joining collections, Calculations,  pipeline processing. etc 

..> it is fastest for the  simple taks 


Aggregation querying:

..> Process and transform data (e.g., group, sort, project, calculate).

..> Use Case : Complex data processing and analytics.

..> it can do the Grouping, joining collections, Calculations,  pipeline processing. etc 

..> Slower for just basic retrieval




Aggretaion pipeline in the MONGO DB:


..> $lookup is used in the aggregation pipeline to perform joins between collections (similar to SQL joins).

..> It brings documents from another collection into your current document based on matching fields.

..> 

the basic syntax is :

{
  $lookup: {
    from: "<foreign_collection>",
    localField: "<local_field>",
    foreignField: "<foreign_field>",
    as: "<output_array_field>"
  }
}

EXample: Join using different field names with let and $expr inside $lookup:


let — to pass a variable from the main collection (orders) :

pipeline-   to filter documents from the products collection

When to use the lookup and localFields and foreignFields:

.> I want to join 2 collections using just one field, and both fields have the same type, and I don’t need any extra filters."


But :

You want to match more than one field?

You want to join on fields that have different names or formats?

You want to add filter conditions while joining?

.> "I need full control. I want to join based on multiple fields, or I want to apply filters inside the join."

db.COLLECTION_11.Aggregate({

  $lookup: {

    from: "COLLECTION_22",

      {

        }
      }

    as: "joinedData"
  }
}

What is $arrayElemAt in MongoDB? :

..> $arrayElemAt is a MongoDB aggregation operator that lets you get a specific item from an array using its index.

> { $arrayElemAt: [ <array>, <index> ] }

<array> = the array you want to pull from

<index> = the position (starting from 0) of the item you want

{ ratings: [4, 5, 3, 2] }

{ $arrayElemAt: ["$ratings", 1] } ➝ 5



What does $first do in MongoDB Aggregation?

..>  $first is an aggregation operator that returns the first value it encounters within each group created by $group.
{ $first: "$<field_name>" }

If you're using $sort before $group, then $first gives you the first value after sorting.

 What does $first mean in MongoDB aggregation?

... $first returns the first value from a group of documents — based on the order they are received by the $group stage.

..> If you skip the $sort, then $first will pick a random first document, depending on how MongoDB internally processes them. This may not be what you want.

WHAT >$lookup + $mergeObjects to Combine Embedded Documents :

$replaceRoot	Replaces the entire document with a new merged structure
$mergeObjects	Combines two objects → here: customerInfo + current order

db.orders.aggregate([
  {
    $lookup: {
      from: "customers",
      localField: "customer_id",
      foreignField: "_id",
      as: "customerInfo"
    }
  },
  {
    $unwind: "$customerInfo"
  },
  {
    $replaceRoot: {
      newRoot: { $mergeObjects: ["$customerInfo", "$$ROOT"] }
    }
  },
  {
    $project: {
      customerInfo: 0,
      _id: 0
    }
  }
])


# What does $replaceRoot with newRoot do?

..> 


$replaceRoot is only used inside an aggregation pipeline.

It replaces the current document entirely with the one you specify.

It does NOT modify the original collection in the database.

Part	What it does
$replaceRoot	Tells MongoDB: “replace this entire document”
newRoot	The new document structure you want
$mergeObjects	Combines two objects into one
["$customerInfo", "$$ROOT"]	Merges customer info first, then current doc




note: This temporarily changes what you see in the output, but your original orders collection stays untouched.

Let’s now understand how MongoDB decides what to keep and what not to keep when we use:

$replaceRoot + $mergeObjects

..> $mergeObjects: [ obj1, obj2 ]

tart with obj1

Then add/overwrite values from obj2

If both have the same key, the value from obj2 will overwrite obj1's value


ex:
{
  $mergeObjects: [
    { name: "Rahul", city: "Delhi" },  // from customerInfo
    { item: "Laptop", city: "Bangalore" } // from original document
  ]
}

o/p:
{
  name: "Rahul",
  item: "Laptop",
  city: "Bangalore"   // This overwrites "Delhi"
}

Because "city" was present in both → the second one (ROOT) wins.

MongoDB merges both, and:

Keeps all unique fields

If any field names clash, the one from "$$ROOT" wins
